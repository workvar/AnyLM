v0.5.1

GA4 + Clarity analytics (replacing PostHog), a first-run setup wizard, and marketing conversion events on the site — with desktop installers for macOS, Windows, and Linux.

### Highlights

- **GA4 + Microsoft Clarity.** Desktop product events go through GA4 Measurement Protocol in main; Clarity loads in the renderer when consent allows. PostHog is removed.
- **Same privacy model.** Soft-ask consent, Privacy settings, and independent field groups still gate what leaves the device.
- **First-run setup wizard.** Guided steps for bundled services, Ollama, optional embed model, and prefs before the main UI.
- **Web conversion events.** Site tracks download/CTA/release views with separate `NEXT_PUBLIC_*` measurement IDs from the desktop app.
- **Activity strip polish.** Tighter ring label layout on the marketing home page.

### What's new and internals

- Replace `posthog-node` with GA4 client + payload helpers; consent-gated Clarity loader; availability skip when IDs are empty.
- Stable product taxonomy (`app_opened` / `app_closed`, auth, projects, `ai_request_*`, reliability) plus web `download_clicked` / `cta_clicked` / `release_viewed`.
- Env swap: `ANYLM_GA_MEASUREMENT_ID` / `ANYLM_GA_API_SECRET` / `ANYLM_CLARITY_ID` (desktop); `NEXT_PUBLIC_GA_MEASUREMENT_ID` / `NEXT_PUBLIC_CLARITY_ID` (web).
- Setup wizard + startup dependency checks wired into boot.
- CI build vars updated for the new analytics secrets.

### Upgrade notes

- Prefer this build over **v0.5.0** if you have not installed yet — analytics stack and first-run setup differ.
- Existing installs that use electron-updater will pick up `latest*.yml` from this release when auto-update is enabled.
- Builds are unsigned unless Apple/Windows code-signing secrets are configured; macOS may need a one-time **System Settings → Privacy & Security → Open Anyway** approval on first launch.
- Configure GitHub/Vercel env for the new GA4/Clarity IDs; do not put `ANYLM_GA_API_SECRET` in `app/.env`.
